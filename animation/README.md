# animation/ — анимации сборки и движений (ExplodedAssembly)

Анимации живут **отдельно от модели**, чтобы правки модели их не ломали, а правки анимации не трогали модель.

переделка деталей (размеры, форма) анимацию не ломает.

## Анимации и модели: одна анимация — один модуль (с 2026-11-13)

Как и код модели (`vanmodel/` — по файлу на подсистему), анимации разложены **по файлу на анимацию**:
`animation/sequences/<имя>.py`. Каждый файл — самостоятельный модуль-данные: от кода модели он не зависит, модель от
него — тоже (она его только читает и проверяет). Поэтому анимацию можно делать параллельно с правками модели.

**Для какой модели анимация** — строка `MODELS` в файле:

```python
MODELS = ['van_v1_rect_pan']   # имя файла модели без .FCStd; 'van_v0' — это и van_v0_T4320, и van_v0_T4100…
MODELS = []                    # пусто — для любой модели (в которой есть все детали)
```

| Анимация | MODELS | Что показывает |
|---|---|---|
| `assembly.py` | любая | снять матрас → настил → поперечины → батареи B2–B4 |
| `drawers.py` | `van_v0` | два ящика багажника старой модели (`Trunk1_Drawer`, `Trunk2_TrayFwd`) |
| `upper_drawer.py` | `van_v1_rect_pan` | верхний ящик (`Drawer_Upper` + ручка) выезжает назад на 1117.6 мм (SLIDEWAY 44″) |

- **К одной модели — сколько угодно анимаций.** `ea_build` берёт сразу несколько файлов (Ctrl+щелчок в окне выбора)
  и для каждого делает свой файл `<модель>_anim_<имя>.FCStd`, например `van_v1_rect_pan_anim_upper_drawer.FCStd` и
  `van_v1_rect_pan_anim_assembly.FCStd`. Одна и та же анимация может стоять на разных моделях — у каждой свой файл.
- Модель при сборке проверяет **только свои** анимации (по `MODELS`) и только свои файлы `<модель>_anim_*.FCStd`;
  остальные в отчёте — строкой «для других моделей». Так же `tools/check_animation.py <модель>.FCStd`.
- `ea_build` на «чужой» модели спрашивает, собирать ли всё равно. `ea_export` пишет `MODELS` сам — по имени файла
  анимации (`van_v1_rect_pan_anim_…` → `van_v1_rect_pan`); если в файле уже был список — добавляет модель к нему, если
  было «для любой» — так и оставляет.
- **Новая анимация на Python** (без мыши): скопировать `upper_drawer.py` под новым именем, поменять `SEQUENCE`,
  `MODELS`, шаги (`name` — внутреннее имя детали из дерева FreeCAD, `vec`, `distance`) → `git push` → `ea_build`.

## Анимация → модель (с 2026-11-11)

При каждой сборке модель **читает анимации** и проверяет их на своей геометрии (`vanmodel/motion.py`). Сами анимации
она не меняет, и ошибка в анимации сборку модели не останавливает.

Откуда читает:
- `animation/sequences/<имя>.py` — то, что записано в репозиторий;
- файлы анимации рядом с моделью (`<модель>_anim_<имя>.FCStd`, а также `*_anim.FCStd`, `*_drawer.FCStd`) — группы
  ExplodedAssembly берутся **прямо из сохранённого файла**, без `ea_export`. Достаточно сохранить файл (Ctrl+S) и
  пересобрать модель. Если файл отличается от `sequences/<имя>.py` и не старее его — в модель идёт файл, а в отчёте
  появляется напоминание про `ea_export`. Новая анимация, которой ещё нет в `sequences/`, тоже подхватывается.

Что проверяет — для каждого шага, в порядке разборки (детали предыдущих шагов считаются уже сдвинутыми):
- **ход:** деталь проходит `vec × distance`, не задевая то, что ещё стоит. ⚠ — упирается в другую деталь (сказано, через
  сколько мм и во что); ⓘ — выходит за кузов (обычно это приём «прилёт из-за кадра»);
- **зазор в конце хода:** к чему деталь подошла ближе 150 мм;
- **порядок сборки** — шаги в обратном порядке, одной строкой.

Отчёт печатается после сводки модели и пишется в `docs/animation_report.md`. Изменили ход ящика или порядок шагов —
после пересборки отчёт покажет, что из этого следует для модели. Отключить: `VAN_MOTION=0`.

Чего пока нет: вращение (Bolt Group) не проверяется; геометрию модели анимация не двигает — если по отчёту нужно
что-то изменить в модели (например, поднять рейку), это по-прежнему делает Claude.

## Как работать

**Сделать или изменить анимацию мышью** (как раньше):
1. Работаете в своём файле анимации (`van_v0_T4320_anim.FCStd`, `van_v0_T4320_drawer.FCStd`, …): Create Simple Group и т.д.
2. Сохраняете анимацию в репозиторий: **Файл → Открыть… → `animation/ea_export.FCMacro` → Макрос → Выполнить макрос**
   (Ctrl+F6). Макрос спросит имя последовательности (`*_drawer` → `drawers`, `*_anim` → `assembly`) и запишет
   `animation/sequences/<имя>.py`.
3. `git commit` + `git push`.

**Получить анимацию на свежей модели** (после правок модели или на другом компьютере):
1. `git pull`.
2. **Файл → Открыть… → `animation/ea_build.FCMacro` → Макрос → Выполнить макрос**.
3. Выбрать одну или несколько последовательностей (`animation/sequences/*.py`), затем модель — макрос сам предложит
   модель из `MODELS` (например, `van_v1_rect_pan.FCStd`).
4. Макрос **скопирует** модель в `<модель>_anim_<имя>.FCStd` (сама модель не меняется), создаст в копии все группы,
   скроет объекты из списка `HIDDEN`, поставит модель «в сборе» и сохранит. ▶ — разобрать, ◀ — собрать.
   Если какой-то детали в модели уже нет — макрос её пропустит и скажет об этом.

Готовый файл анимации можно дальше править мышью и снова экспортировать — круг замыкается.

**Править `sequences/<имя>.py` руками** тоже можно (это обычный Python-файл со списком `STEPS`), но повторный
`ea_export` с тем же именем перезапишет файл целиком — вместе с вашими комментариями.

## Формат `sequences/<имя>.py`

```python
SEQUENCE = 'drawers'
MODELS = ['van_v0']            # для каких моделей; [] — для любой
STEPS = [                      # порядок РАЗБОРКИ, как группы в папке ExplodedAssembly
    {
        'label': 'Ящик выдвинуть',
        'kind': 'simple',      # simple | bolt
        'distance': 914.4,     # мм
        'steps': 90,           # кадров
        'step_time': 0.01,     # с между кадрами
        'revolutions': 0.0,    # обороты (Bolt Group)
        'parts': [
            {'name': 'Trunk1_Drawer', 'vec': (-1.0, 0.0, 0.0),
             'rot_axis': (-1.0, 0.0, 0.0), 'rot_center': (0.0, 0.0, 0.0)},  # Label детали
        ],
    },
]
HIDDEN = ['Trunk1_Drawer_Out']   # что скрыть в файле анимации
```

Длина `vec` масштабирует ход детали: в одной группе деталь с `vec = (-0.5, 0, 0)` проедет половину `distance`
одновременно с остальными (так можно сделать телескопическую направляющую). Группы проигрываются строго по очереди.

## Особенности дополнения ExplodedAssembly (FreeCAD 1.1)

- Дополнение двигает **сами детали** (меняет Placement) и запоминает их «собранное» положение при создании группы.
  Поэтому анимацию делаем только в копиях модели, а не в `van_v0_T4320.FCStd`.
- `trajectory_line` — только пунктир-подсказка; иногда «выпадает» из своей группы в папку ExplodedAssembly — удалить (Del).
  `ea_build` эти линии не рисует.
- Появления детали «из ниоткуда» дополнение не умеет — пока приём «прилёт из-за кадра» (большой Distance).
- Верстак не обновлялся с 2024 г. (github.com/JMG1/ExplodedAssembly); ошибки — в окне «Отчёт».
